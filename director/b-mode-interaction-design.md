# 数字人口播工作台：交互与开发合同

状态（2026-09-24）：原操作台 `/` 的“数字人口播”主视图已嵌入可操作的 B 模式交互；`/director/b-mode-console.html?embed=1` 只是该视图的内部模块，直接打开旧独立地址会回到原操作台。A 模式编导台、制作台、素材库仍在同一导航内。文案、设置和人工分镜草案保存在当前浏览器，角色图/音色样本刷新后须重选。B 模式生成入口现已接入 TalkCraft 卡片驱动链：现成音色 TTS → 已确认分镜的帧级映射 → 语义/素材类型卡片选择 → `DynamicVideo + TemplateAdapter` → 有声 MP4；人物镜头叠加静态角色图角标。它没有调用火山引擎声音复刻或 RunningHub，也没有生成数字人口型。旧照片配音试做接口已移除，不再作为 B 模式入口。

## 用户输入

| 输入 | 操作台行为 | 生产合同 |
| --- | --- | --- |
| 角色图 | 一张 PNG/JPG/WebP；本地预览、替换或移除 | 同一角色图供本片已确认的口播单位复用；运行目录保留原图和规范化版本 |
| 文案 | 完整文案，改动后分镜确认失效 | 生成整段 TTS 与时间戳，口播和非口播镜头共用同一主音轨 |
| 音色 | 现成音色或已训练成功的复刻音色 | 保存提供方、音色 ID 和版本；克隆音色不得静默回退成 Edge TTS |
| 复刻样本 | 可选短音频，仅供音色训练和本地试听 | 不进入视频时间线；V3 训练/查询与正式合成分离，成功音色复用 |
| 人物背景 | 保留、检测后处理、仅绿幕抠绿 | 真实视频非稳定绿幕时不得直接色键；原始成功视频永久保留 |
| 人物背景兜底 | 在同一 B 视图搜索文件名/分类/标签，选中一条视频，可移除 | 只供未单独选择视频的 `person` 镜头使用；人物图未抠像 |
| 逐镜视频 | 分镜页为每句自动推荐，展示缩略图与理由，也可逐句搜索、替换或清除；相邻镜头禁止使用同一视频，匹配不到替代素材时标记待选 | `scene.videoPath` 独立保存；服务端逐项核对素材库索引和实际 MP4，静音代理在人物、图解、素材镜头都可使用 |

首版设计稿的文件大小提示沿用已有 B0 图片上限（7 MB）和用户提供的火山引擎 V3 样本上限（10 MB）。正式接入时服务端还需检查文件内容、像素尺寸和可解码性，不能只信浏览器的文件名或 MIME。

## 页面流程

1. **输入**：选一张角色图，填写文案并选择音色；可在同一 B 视图从素材库搜索并选择人物镜头的背景视频。选择“声音复刻”可预览本地样本，但训练按钮不出现，直到 V3 transport 和费用闸门真正接通。
2. **分镜**：页面按与 B0 TTS 一致的句末标点拆成句段，全部标为“待确定”；用户可逐句选择数字人口播、图解/文字或素材画面。点击“为各镜头匹配视频”后，按文案与现有素材标签推荐主题近似候选；短承接句可沿用相邻镜头并明确标注。没有可靠候选时保留“待选素材”，不静默硬配。每行可搜索素材库并人工替换，人工选择不会被再次自动匹配覆盖。验收时可显式载入 `b-mode-acceptance-script.txt` 全文与 19 句固定人工分镜；非空 B 草稿会先备份，并可从页面恢复，不会自动覆盖 A 输入。这仍不是编导模型的语义规划。占位测试运行后，服务端才把 TTS 子段与这些句段严格对齐为整数帧；对不上直接失败。文案变动后必须重建并重新确认。
3. **生成前检查**：展示角色、音色、抠像偏好、逐镜视频数量、人物背景兜底、数字人镜头数和相邻口播镜头合并后的单位数。可导出不含媒体字节的方案 JSON。输入齐全、分镜确认且使用现成音色时可运行 1–1200 字、每句不超过 80 字的 TalkCraft 卡片样片；卡片来自当前注册表和 `DynamicVideo` 组件映射，素材镜头保持逐镜视频底层，人物镜头保留静态角色角标。复刻音色、绿幕抠像和 RunningHub 真实生成不在本测试内。真实数字人提交按钮始终禁用。
4. **成片**：通过 `/director/b-mode-video-preview.html?id=...` 预览和下载 TalkCraft 卡片样片，显示实际时长、分镜帧段、卡片数量和 `isDigitalHuman:false` 的状态。预览器从原 MP4 取视频帧绘制到画布；原生 MP4 播放层在内置浏览器黑屏且原生 `<audio>` 控件曾使标签崩溃，因此将同一运行的 TTS MP3 交给 Web Audio 播放并用它作为画面时钟。音频接口为 `GET /api/b-mode/placeholder/audio?id=...`，同时提供 MP3 下载作本机核对。原始 MP4 不改写。页面刷新后恢复本浏览器最近一次成功卡片样片。未来 RunningHub 数字人产物必须作为另一类结果呈现，不能把卡片样片或 Mock 充当数字人结果。

## 全片排版合同

排版由 `template/src/DynamicVideo.tsx` 与 `TemplateAdapter` 的统一卡片/字幕层负责，不能为单个镜头复制一套 CSS 分支：

- 每个镜头的 `subtitle` 是独立的内容型副标题；不能使用“图解 / 文字镜头”“素材镜头”“数字人口播镜头”作为成片副标题。分镜页允许编辑副标题，验收夹具为 19 个镜头提供固定副标题。
- `visualText` 只用于画面展示，`text` 保留完整口播原文。画面文案按显式换行或中文标点拆成最多三组；超过三组时合并为三组，保持语义顺序。
- 人物、图解、素材三类镜头共用同一行组规则，但使用各自安全区宽度、字号范围和文字面板。字号按每一行的实际字符数计算，并保留左侧强调线；长句允许缩小字号，不能溢出或依赖随机换行。
- 画面文案可以清理引号、破折号和多余空格，但不能改变配音原文。修改配音文字必须同时重新生成 TTS 并重新对齐时间轴。
- 交付前至少抽查短句、两段句、三段句、长句、人物镜头和素材镜头；单个镜头修复后必须回到全片排版规则验证，不得只保留镜头特例。

界面草稿状态只存在于同源浏览器；在原操作台切换 A/B 视图时保留 B 草稿，角色图和声音样本刷新后须重选。B 文案为空时可以显式从编导台当前输入框导入文案；不自动同步，不覆盖非空 B 草稿，也不改写 A 模式输入。B 草稿不写 A 模式的 `director/_input.txt`、分镜或渲染目录。导出 JSON 不包含样本字节、凭据或外部任务 ID。

## 生产调用顺序

1. 保存隔离的 B 项目输入版本。检查已成功 TTS、已训练音色和已生成数字人视频，匹配时直接复用。
2. 对整段文案使用所选音色合成一次 TTS，并记录句段/帧级时间。若选择复刻音色，先查询训练状态；不允许以其他音色替代。
3. 编导给每镜确定 `subject`、原文和时间范围，用户校准并确认。只对确认的 `person` 时间段编排 RunningHub 单位；相邻连续片段可合并，但须保留与整段 TTS 的时间映射。
4. 向 RunningHub 只提交缺失的已批准单位。用户提供的工作流示例使用 `nodeInfoList` 传图片、音频、尺寸、提示词、抖动与缩放；这些节点 ID 是待实测的工作流版本，不应在未核对真实 MP4 输出前写死为生产合同。
5. 查询任务并保存实际 MP4 到本地，核对视频/音频轨、时长、口型及临时 URL 时效。成功产物保留；失败只重试失败单位。可选抠像生成独立派生产物，不能覆盖原 MP4。
6. Remotion 消费生成的人物视频与其他镜头素材。选择素材库背景时，先核对人物视频能否抠出前景，抠像合格后再叠到背景视频上；未抠像不得声称背景已替换人物原背景。整段 TTS 只播放一次，背景视频静音；若 RunningHub 输出改变音频节奏，应先校准口型，不能直接静音拼接。逐镜 QA、浏览器播放和用户验收分别记录。

## 建议接口与状态

下表区分已实现占位测试与待实现真实生成。新增前确认每个 `METHOD + PATH` 的唯一所有者，并与 A 模式任务/文件隔离。

| 方法与路径 | 输入/输出要点 | 当前状态 |
| --- | --- | --- |
| `POST /api/b-mode/project` | 角色图、文案、音色引用；返回项目 ID 与输入版本 | 未实现 |
| `POST /api/b-mode/voice-clone` | 可选样本与费用确认；返回训练任务/音色 ID | 未实现 |
| `GET /api/b-mode/voice-clone?id=...` | 查询训练状态和可用音色 | 未实现 |
| `POST /api/b-mode/plan` | TTS 时间轴、逐镜语义与数字人生成单位 | 未实现 |
| `POST /api/b-mode/plan/confirm` | 锁定分镜和输入版本 | 未实现 |
| `POST /api/b-mode/generate` | 显式授权后仅提交缺失单位 | 未实现 |
| `GET /api/b-mode/run?id=...` | 持久化状态、任务 ID、产物和错误 | 未实现 |
| `GET /api/b-mode/acceptance` | 返回固定全文与 19 句人工验收分镜，无外部调用 | 已实现，验收夹具 |
| `POST /api/b-mode/material-match` | 逐镜返回素材候选、匹配理由或待选状态，无媒体生成调用 | 已实现，标签近似匹配 |
| `POST /api/b-mode/placeholder` | 角色图、文案、现成音色、已确认句段；启动独立 TTS/Remotion 测试任务 | 已实现，占位测试专用 |
| `GET /api/b-mode/placeholder/video?id=...` | 返回已完成的有声占位 MP4 | 已实现，占位测试专用 |
| `GET /api/b-mode/placeholder/audio?id=...` | 返回同一运行的 TTS MP3，供 Web Audio 预览与下载 | 已实现，占位测试专用 |
| `GET /api/library/list?q=...&limit=...` | 从现有素材库按文件名/分类/标签搜索视频 | 已实现；B 视图复用 |
| `GET /api/b-mode/video?id=...` | 已有 B0 样片视频接口；正式 B 结果需另定合同 | B0 已实现 |

持久化状态建议按 `draft → tts_ready → planned → approved → submitted → downloaded → rendered → verified` 前进，失败保留阶段与原因。任何输入版本改变，都应使依赖它的后续确认失效，但不删除已有成功音频、数字人视频或收费资产。凭据只在服务端配置，页面与导出方案不得包含密钥。

## 验收边界

- **交互设计稿**：四步导航、文件预览、音色模式切换、文案变更失效、逐句类型选择、连续人物单位统计、本地恢复和 JSON 导出在桌面与手机宽度可操作。
- **图片占位测试**：用一张角色图及含人物/非人物镜头的文案，经现成 TTS、严格逐字和帧段闭合映射、Remotion 实际渲染为有声 MP4；逐镜素材视频作为静音底层，报告列出有视频和待选镜头数。抽看三类画面、`ffprobe` 音视频轨、浏览器播放及报告中的 `isDigitalHuman:false`、`runningHubCalled:false` 与 `backgroundKeyApplied:false`。占位图不是口型或抠像验证。
- **接口合同**：服务端持久保存输入、任务和素材来源；图片/样本文件校验；训练状态和 RunningHub create/query/download 的错误、超时、重试与重复请求处理。
- **真实链路**：一条实际复刻音色（若启用）与一条实际 RunningHub MP4，完成从角色图/文案/音色到 TTS、分镜、数字人、抠像（若选）、整片播放的验证；确认口型、单音轨、时间码和产物复用。没有实际付费授权时停在调用前。

主流程依据见 [b-mode-workflow-design.md](b-mode-workflow-design.md)；本页面不替代 B1 真实运行验收。

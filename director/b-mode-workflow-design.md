# B 模式工作链路设计（RunningHub 数字人口播主导）

状态：B0 TTS 静态人物图测试和 B 视图图片占位分镜测试均已完成独立 HTTP 出片验证；B1 RunningHub 数字人口播主轨仍为设计稿，尚未接通或完成真实数字人视频端到端验证。此前 B1 草案把口播视频视为外部拍摄输入；现按用户确认的来源改为 RunningHub 生成。

原操作台中的数字人口播视图及其状态/接口/验收合同见 [b-mode-interaction-design.md](b-mode-interaction-design.md)。该视图现可运行独立的“图片占位样片”测试，但不是 B1 RunningHub 数字人生成入口，不验证口型或抠像。

## 0. 已实现的 B0 测试链路（2026-09-23）

当前 B 模式主路径保持 `BModeBaseline`：操作台收集角色图、完整文案、现成音色、已确认逐镜主体和视频素材；`director/b-mode-tts.py` 生成或复用整段配音与帧级时间；基线渲染保持已验收的素材底层、人物构图和字幕排版。`--talkcraft` 只作为隔离实验开关，用于验证 `DynamicVideo + TemplateAdapter` 卡片渲染，不代表完整编导 skill 已迁移。`GET /api/b-mode/placeholder/video?id=...` 与预览器继续复用原有文件流合同；真实数字人仍未接入 RunningHub，也不产生数字人口型。产物在 `director/b-mode-runs/<id>/`、`template/public/b-mode/<id>/` 和 `template/out/b-mode/`，不覆盖 A 模式文件。

B0 优先使用 Edge TTS；默认音色和正常语速下，在线语音没有返回音频时才尝试本机 Windows 中文离线语音，并在 `timing.json`/`report.json` 标记 `voiceEngine`。文案上限为 360 字，供约一分钟的样片测试。`timing.json` 同时记录由音频 PCM 解码得到的逐帧 `audioLevels`；声纹按 Gallery 的 `voice-waveform-live` 镜头卡和准确 demo 适配 64 条声纹，用真实音轨强度驱动。开场文字按 `type-assembly-moves` 的 `split-text-stagger` demo 逐字裂升；讲解流程可按 `row-embed` 的逐行落位节奏适配。每次运行可在独立 run 目录放入 `avatar.png`，以用户静态图片替代内置插画；不生成数字人，不做口型同步。完整的 Ink Press 宣传片模板需要目标产品的真实页面截图，不宜整片套进此测试。Edge TTS 句边界元数据与原文分句一致时采用句首时间戳；Windows 离线回退逐句合成并按实际 PCM 长度拼接，标记 `offline_segment_assembly`；其他元数据缺失或不匹配时在字数估算附近寻找音频低谷，标记 `audio_pause_assisted_estimate`。这不是逐字对齐。验证范围仅为 TTS → Remotion → MP4 → 独立本地 HTTP 预览，不代表 B1 RunningHub 数字人口播已接通。

音色和语速使用在线 Edge TTS；选择非默认值后若在线配音失败，任务直接报错，不会用无法保持该设置的离线声音替代。

## 0.5 文案驱动画面编排（B0 后续验收门槛）

当前 B0 已按有限规则选择镜头：明确列举才拆成信息卡，谈声音才用声纹，问句/对比/收束各有对应画面；未匹配时使用中性字卡。每次运行保存 `scene-plan.json` 的原文、时间、选型与理由。此规则没有产品理解、素材检索或自主分镜能力，也没有人工校准界面。

B1 下一阶段需扩展 `scene-plan.json`，在渲染前由用户校准：逐句记录原文、表达意图（引入/问题/机制/步骤/证据/对比/结论）、要传达的视觉信息、主体与素材来源、Gallery 镜头卡及变体、卡片选择理由、时间范围和缺素材状态。规划器须读取完整文案及项目功能/素材清单，先列必讲信息与能量曲线，再逐句映射；选卡时查 Gallery 索引、卡片全文和准确 demo 源码。缺证据或页面素材时显式留空待补，不用不相干的人物插画或随机模板冒充。

操作台需先展示可编辑的分镜预览，用户确认后才按锁定版本渲染；改文案必须重新规划或显式确认保留映射。验收用两段语义不同、句数相同的文案测试：分镜主体和卡片选择应随内容改变，且每个镜头能追溯到原句及选卡依据；核对素材存在、帧段闭合、成片逐镜与分镜一致。只有固定按句序轮换或关键词分类，不能声称已实现 skill 的自主创作链路。TTS 时间轴在获得真实句/词级对齐前继续标记估算，不声称精准同步。

## 0.6 图片占位分镜测试（2026-09-24）

原操作台 B 视图已接 `POST /api/b-mode/placeholder`：用户上传一张角色图、填写 1–1200 字文案、选现成音色并逐句确认镜头主体；每句最多 80 字。任务使用 B0 的 TTS 产生整段口播与帧级句段时间，对照确认分镜逐字匹配，把 TTS 子句合回用户选定的句段；只要原文或帧段不一致就失败。`person` 镜头以静态角色图占位，`graphics` 使用文字卡，`material` 显示待补素材；Remotion 输出有声 MP4，可从 `GET /api/b-mode/placeholder/video?id=...` 在原操作台播放和下载。运行输入、时间线、海报、报告与 MP4 按 UUID 隔离，不覆盖 B0 或 A 模式产物。B0 自身的 360 字上限保持不变。

固定验收文案保存在 `b-mode-acceptance-script.txt`，19 句人工分镜主体保存在 `b-mode-acceptance-plan.json`。`GET /api/b-mode/acceptance` 只读取这两份夹具供操作台显式载入；载入前备份非空 B 草稿并可恢复，不改写 A 输入。每次占位测试应核对原文完整、19 个句段和实际输出总时长，不用几秒短句代替全文测试。

本次 520 字、100.01 秒全链条占位测试及其句首时间修正证据见 [b-mode-acceptance-evidence.md](b-mode-acceptance-evidence.md)。占位专用 TTS 使用 `--preserve-sentences` 以保留原句，B0 默认长句拆分行为不变。

基线报告写明 `kind=baseline-b-mode-preview`、`renderer=BModeBaseline`；卡片实验报告写明 `kind=talkcraft-card-preview`、`renderer=DynamicVideo + TemplateAdapter`。两者都不调用 RunningHub，不训练/合成复刻音色，不执行绿幕抠像，也不验证数字人口型。卡片实验只验证卡片注入、逐镜素材、TTS 时间闭合和浏览器有声播放，不能替代完整语义编导、SHOTBOOK、版式轮换和 preflight 验收。

B 视图可再选一条素材库视频作为人物镜头背景：`GET /api/library/list` 按名称/标签搜索，服务端只接受索引中存在的 MP4，生成独立静音 720p 代理，在 `person` 镜头底层循环，原素材不覆盖。静态角色图仍保留其原背景；`backgroundVideoApplied=true` 仅表示底层视频出现，`backgroundKeyApplied=false` 表示尚未抠出人物。真实绿幕数字人的背景替换仍需独立抠像验收。

## 1. B1 定位与现状

B 模式的口播画面均来自 RunningHub 生成的数字人视频，Remotion 字幕、图解、证据素材、转场为辅。用户上传一张角色图、提交定稿文案并选择 TTS 音色；音色可来自已接入的现成音色，未来也可选择已训练的复刻音色。系统按所选音色生成整段口播音频，再将角色图和需要人物出镜的音频片段交给 RunningHub。用户不上传本片的口播音轨；复刻时上传的短音频仅用于训练音色，不进入视频时间线。已成功生成且匹配角色图、文案、音色 ID/版本和音频版本的本地视频应优先复用。数字人调用只针对编导确认需要人物出镜的时间段；非口播画面不触发调用，旁白仍须连续。与 A 模式的渲染产物和任务状态隔离。

可选声音复刻是独立的一次性准备流程，不是每次渲染都训练。按用户提供的火山引擎文档，优先使用 V3 `voice_clone` 训练接口：样本音频最大 10 MB，以 base64 音频数据提交；用 `get_voice` 查询，状态为 2（Success）或 4（Active）时才允许把 `speaker_id` 放入音色选择。保存音色 ID、样本版本和训练状态，复用已成功音色；不把密钥或样本原文写入前端。文档提示试听文本可能产生合成费用，后付费音色首次正式合成还可能触发音色槽位费用。实际费用与可用模型需在接入时重新核对官方规则，付费调用只在用户确认后执行。当前项目尚无火山引擎声音复刻或克隆音色 TTS transport。

当前 B0 静态图片测试按钮已接通，但正式生成/规划入口仍固定执行 `tts.py` 和 `build-storyboard.mjs --mode=A`。分镜器已有 B 的 `person` 预排（目标比例 60%）和 `pit.subject=person`，但它按普通素材标签查视频，找不到时登记 AIGC 占位；没有 RunningHub 数字人任务、结果复用、专用人像主轨、片段源入点或原声音画同步。`DynamicVideo.tsx` 只消费 `shot.material`，素材视频静音且镜头开始时从片源起点播放；全局配音取 `storyboard.audio`。这些能力不能视为已接通 B 链路。

## 2. B1 操作台路径与阶段闸门

1. **选择 B 与准备输入**：操作台只要求用户上传一张角色图、提交定稿文案并选择音色；已训练的复刻音色与现成音色一样作为选项，若用户要新复刻则另走一次样本上传和训练。系统对整段文案合成一次 TTS，保存音频与句段时间信息，不提供必填口播音频上传。该角色图可复用于本片多个数字人片段。先查本地已成功生成的视频及其角色图、文案、音色 ID/版本和音频版本；匹配时复用，不重新上传或生成。保留原图片、音色记录、TTS 音频和付费产物。
2. **先规划再生成**：以整段 TTS 音频为唯一主时间轴，编导标记需要数字人出镜的 `person` 时间段，连续且同人物的片段可合并为生成单位。数据、证据、步骤等镜头由 Remotion 或已有素材承担；人像占比是编辑目标，不是必须生成的配额。操作台展示分镜和待生成单位，用户确认后才允许付费调用。
3. **RunningHub 生成与入库**：只对没有匹配成功产物的已批准单位，从同一条 TTS 主音轨裁出对应片段，与同一角色图一起上传，按已核实的工作流节点映射提交任务并查询状态。记录任务 ID、输入版本和输出节点；仅接受实际返回并可解码的视频文件。结果 URL 有时效，成功后及时下载到独立运行目录，使用 `ffprobe` 检查时长、视频和音轨。失败仅重试明确失败的单位，不覆盖成功视频。
4. **可选人物抠像**：先检查真实生成视频的背景。只有背景确为稳定、纯净的绿色时才使用色键抠绿；若背景复杂或绿色污染人物边缘，则需人像分割/视频抠像，不能把提示词视为绿幕保证。保留未处理的成功 MP4，另存透明人物层或遮罩，并检查头发、手、衣物边缘、绿边、帧间闪烁及音画同步。此能力当前尚未实现，也未拿真实 RunningHub 视频验证。
5. **时间线与音轨**：记录每段数字人视频在整段 TTS 中的对应区间、片源入点、时间线起点和帧长；旁白在非人物镜头中仍连续。整段 TTS 只播放一次，生成视频自带的同源音频不得叠加；若 RunningHub 改变音频节奏导致口型与 TTS 不同步，应阻断并校准，不强行静音后拼接。时间单位统一：媒体探测使用秒，编辑与渲染合同使用 30 fps 整数帧，并记录源帧率换算。
6. **逐镜校准与出片**：同一时间线上预览数字人或抠像人物层、旁白、字幕、图解和覆盖素材；核对口型、人物边缘、字幕、安全区与镜头切换。先渲代表性镜头，再渲全片；输出 MP4、分镜/素材清单和质检报告。
7. **验收与后期**：逐镜检查口型与音频同步、抠像边缘和帧间稳定、片段边界、无重复声音、无黑帧和素材缺失；抽帧并在浏览器播放验证。通过后才考虑导入 `workbench`，目前该入口仍未接通。

## 3. B1 最小数据合同（建议新建 B 工程清单，勿覆盖 A 的现有成片）

```json
{
  "mode": "B",
  "fps": 30,
  "voice": "zh-CN-YunxiNeural",
  "sourceVideo": "director/b-runs/example/person-001.mp4",
  "sourceKind": "runninghub",
  "sourceAudio": "director/b-runs/example/tts-voice.mp3",
  "edl": [{ "source": "director/b-runs/example/person-001.mp4", "sourceInFrame": 0, "sourceOutFrame": 300, "timelineFromFrame": 0 }],
  "shots": [{
    "id": "b-001", "fromFrame": 0, "durationInFrames": 90,
    "subject": "person", "source": "director/b-runs/example/person-001.mp4", "sourceInFrame": 0,
    "text": "示例口播", "overlays": []
  }]
}
```

- `edl` 与 `shots` 的时间范围必须在 30 fps 整数帧上闭合；`sourceInFrame` 属于对应源媒体，不得把每个镜头都重置到片源零帧。若多源或变速，明确保存时间映射，不能只用一个入点代替。
- `sourceVideo` 指向已下载并验证的 RunningHub 本地成功产物；任务 ID、图片/音频来源及输入版本另存于运行清单，用于复用和审计，不以临时 URL 作为长期素材路径。
- `voice` 保存用户选择的 TTS 音色 ID；复刻音色另保存训练版本与状态，样本音频只属于音色登记，不作为 `sourceAudio`。`sourceAudio` 指向由所选音色生成的整段 TTS 主音轨，而非用户上传的口播音频。生成视频若自带相同声音，渲染时不得重复播放。原始文件和剪辑决策分离，避免覆盖或删除成功视频。
- 与既有 `storyboard.json` 的 `pit/shotCard/material` 兼容关系通过显式转换层实现；不要直接改变 A 模式字段语义。每个 B 项目的工作产物、任务状态和导出目录独立，避免并发覆盖全局 `director/timing.json`、`storyboard.json`、`props.json`、`template/out/dynamic.mp4`。

## 4. B1 接入顺序与验收标准

1. 先实现音色选择、整段 TTS 时间轴、数字人生成单位、成功产物复用与隔离存储；用已有 RunningHub 成功 MP4 验证读入和音画同步。声音复刻独立接入 V3 训练/查询与克隆音色合成，不能用 B0 的 Edge TTS 冒充复刻音色。
2. 再接 B 分镜校准、RunningHub 上传/提交/查询/下载和逐镜小样；付费按钮只有在输入、节点输出合同和用户授权均成立时才可点击。
3. 最后接整片渲染、任务恢复、质检和 workbench 导入。A 模式回归验证必须保持现有 TTS→分镜→渲染链路。

验收用一个真实 RunningHub 数字人任务走完整链路：角色图 + 文案 + 音色 → 整段 TTS → 分镜确认 → 授权生成 → 查询并保存 MP4 → 有声小样 → 全片 → 浏览器播放 → 导入工作台。逐镜源入点正确、声音无重复/漂移、缺素材有明确阻断、失败可恢复；Mock、文档或单节点通过不等于全链路通过。任何第三方付费生成、生产任务重跑或素材删除均需用户单独确认。

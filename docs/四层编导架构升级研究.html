四层编导架构升级研究

Video ShotCraft · 编导子系统深度诊断与升级方案 · v1.1 · 2026-09-21
一句话结论：现有"四层坑位模型（L0 模式 / L1 主体 / L2 内嵌元素 / L3 位置）"与 taxonomy"三级叙事分级（L1 叙事 / L2 子类 / L3 效果池）"两套体系并存但互不联动—— 叙事分级在选卡，坑位模型只贴标签，且 67 张效果卡全部缺少语义元数据驱动。升级方向：把两套体系合流为一条 5 层统一决策链（L0 模式 → L1 叙事 → L2 语义子类 → L3 镜头卡 → L4 坑位），并接入 gallery 已有的 157 张卡片语义库，让"镜头运用"从随机/贴标签变成"语义 + 能量 + 模式"可推演决策。

一、现状盘点：约定 vs 落地

体系来源层级落地状态
四层坑位模型 director/script-generation-design.md §5 L0 全局模式(A/B/C) · L1 镜头主体(remotion/local-material/aigc-material/person) · L2 内嵌元素(text/image/video-local/video-aigc) · L3 内嵌位置(background/element) ✓ 输出含 pit（mode/subject/content/position）
叙事分级 director/taxonomy.json L1 叙事类型(6：hook/pain/claim/proof/quote/cta) · L2 语义子类(21) · L3 效果池(67 卡) ✓ 选卡主线

二、深度诊断：5 个结构性缺口

G1 · 双模型割裂 —— pit 与 slot 自相矛盾

pit 由独立表 pitByL2[l2][mode] 生成，slot/materialRole 由 resolveSlot(shotCard) 前缀规则生成——两条独立路径，无一致性校验。实测矛盾：

镜头l2pitByL2[A]（pit 输出）resolveSlot（slot 输出）矛盾
data/图表datasubject=local-material · position=background（素材做底）slot=data-show · materialRole=inline-element（素材进图表）pit 说素材做底，slot 说素材进图表
typography/文字definitionsubject=remotion · position=elementslot=text-hero · materialRole=backgroundposition 与 materialRole 打架（element vs background）

结果：坑位模型（L0-L3）没有真正驱动输出，只是贴标签——这正是"镜头运用混乱"的深层结构原因之一。

G2 · L3 效果卡无元数据接入 —— 语义库闲置

选卡只按卡名关键词打分（节奏 + 情绪 + 降权）。而 library.json 每张卡已有现成的 energy（能量：高/中/低）、intention（意图：这段卡想拍成什么）、duration（时长体质）、 summary/use（适用场景）——67 张 L3 卡中 65 张可精确命中（97%），完全可做"叙事能量匹配"： hook 要瞬时高能、quote 要收束低能、data 要信息持续，全部有据可依。

G3 · 模式（A/B/C）只贴标签不参与决策

L0 模式仅写入 pit.mode，选卡与素材匹配完全不区分模式。A 模式（模板主导）下 camera 叙事卡 与 typography 文字卡同权竞争；B 模式（人像主导）没有把素材主体卡加权；C 模式（AIGC 主导）没有氛围卡偏好。

G4 · 坑位组合无合法性校验

任意卡 × 任意模式 × 任意叙事都能输出，没有约束矩阵。转场卡（transition-slot）在中间叙事位出现、 rhythm 节奏卡在 cta 收尾位出现、B 模式的 person 主体从未落地——结构性错位无人拦截。

G5 · 无反馈闭环

渲染后用户观感（"这卡不合适"）无法回写驱动选卡。现有 usage.json 只记使用次数， 没有用户负反馈通道。

三、升级方案：5 层统一决策链

把"叙事分级"与"坑位模型"合流为一条可推演决策链，彻底解决"同名不同义"与"两套体系打架"：

L0 模式A/B/C 全局选择 + 全局情绪基调
→
L1 叙事hook/pain/claim/proof/quote/cta（已有）
→
L2 语义子类21 类 · 语义规则命中（已治理）
→
L3 镜头卡67 卡 · 元数据打分（升级）
→
L4 坑位slot + materialRole + pit 一致性（升级）

U1 · L4 坑位一致性引擎

pit 不再查独立表，改由 resolveSlot 结果反推（单一权威来源），保证 pit 与 slot/materialRole 永远一致：

slot反推 pit素材角色
text-hero{subject:remotion, content:{type:text}, position:element}background（素材做底）
data-show{subject:local-material, content:{type:video-local}, position:element}inline-element（素材进图表）
case-show{subject:local-material, content:{type:video-local}, position:background}hero（全屏主体）
process-show{subject:remotion, content:{type:video-local}, position:element}split（分屏嵌入）
transition-slot{subject:remotion, content:{type:text}, position:element}none（纯转场不配素材）
compare-slot{subject:local-material, content:{type:video-local}, position:split}split（左右对比）

pitByL2 降级为兜底表（resolveSlot 未命中时使用）。

U2 · L3 镜头卡元数据评分

启动时加载 gallery/api/library.json → 建 name→card 索引（65/67 命中，2 个 variant 用父卡兜底）→ 选卡打分新增两项：

  • energy × 叙事匹配（+10）：hook/pain 偏好"高/瞬时冲击"卡；proof/claim 偏好"中高/信息持续"卡；quote/cta 偏好"低/收束"卡
  • duration 体质校验：stretch 通用；fixed 需在推荐时长 ±15% 内（超出直接淘汰）；loop 仅金句/收尾（quote/cta）可用

与现有节奏（fast/loop）、情绪风格、使用降权合并打分——排序取最优（可同分随机轮换）。

U3 · 模式差异化加权（L0 真正参与决策）

模式卡类别偏好（+15）降权（-10）
A Remotion 主导typography / data / ui-entrance / interaction / opening / outro纯素材叙事卡（camera 叙事位降为 +5）
B 人像口播主导camera / opening / effects（背景感强、可作人像后景）纯文字卡
C AIGC 素材主导effects / rhythm / transition（氛围卡）密集文字卡

U4 · 组合合法性矩阵

约束规则违例处理
转场卡transition-slot 仅组间转场位（首尾除外），materialRole=none 不配素材换同池次优卡
节奏卡rhythm 类卡 A 模式仅 proof/pain 可用换同池次优卡
人像主体pit.subject=person 仅 B 模式；B 模式文字卡降级为标注卡模式不符 → 重选
收尾cta 位只用 outro/ 卡（L3 池已约束）已天然满足

U5 · 反馈闭环（P3.5 可选）

分镜校准卡增加「👎 此卡不合适」按钮 → POST /api/card/downvote → 写 director/usage.json 的 userDownvote[card] 字段 → 下次选卡 -30 强降权。复用现有 usage 机制，schema 不变。

四、落地计划（增量 · 不破坏 C1-C7 收敛节点）

阶段内容改动面验收
阶段 1 U1 pit 一致性引擎 + U2 元数据评分 仅 build-storyboard.mjs（加载 library.json + 反推 pit + 打分扩展） 真实文案重跑：pit 与 slot 全一致；19 镜头能量匹配叙事；schema 不变
阶段 2 U3 模式加权 + U4 合法性矩阵 同上 + taxonomy.json 增加合法性规则段 A/B/C 三模式各跑一遍：模式差异化生效、无违例组合
阶段 3 U5 反馈闭环 console-ui.html + console-server.mjs 点「不合适」→ 重跑该镜头换卡

五、风险与边界

  • library.json 卡名与 L3 池命中 65/67（97%），2 个 variant（crash-impact、clipcard-looping）用父卡元数据兜底，无缺卡风险
  • fixed 体质卡较少（约 70/214），选卡主要在 stretch 池内，不会缺卡
  • 所有改动在 build-storyboard.mjs 决策层内，storyboard.json 输出 schema 不变——C2 收敛节点稳定
  • library.json 由上游维护，本地只读引用；版本漂移时降级为"无元数据 = 中性分"
  • 本轮已完成的前置治理（L2 语义选择 + 卡重复硬剔除 + 情绪风格）将保留，与 U1-U4 合并生效

六、实施落地记录（v1.1 · 已实施）

✅ 主体决策层（坑位预排）已上线

build-storyboard.mjs v4.1：L0 模式后先预排 subject（remotion / local-material / person / aigc-material）， 再按主体分支决策——模板主体走双向赋权选卡，素材主体纯素材全屏（shotCard=null），AIGC 主体登记标记（渲染暂用 Fallback 渐变兜底）。 MODE_PRESET 三模式配置：A 模板主导(70/25/5) · B 口播主导(person 60) · C AIGC 主导(aigc 55)。

✅ 动态降级链

素材主体候选 → 检索素材库（语义+时长+情绪）→ 命中用素材；未命中回退模板兜底（渐变+关键词占位）； 抽象/特殊叙事（素材与模板都不合适）→ AIGC 兜底（C 模式主通道、A/B 模式兜底）。主体比例是跑出来的，不是定死的。

✅ U1 pit 一致性引擎

pit.subject 统一 = 预排主体；坑位布局由 SLOT_TO_PIT[slot] 反推（content/position），pitByL2 仅兜底——pit 与 slot/materialRole 不再打架。

✅ U2 镜头卡元数据评分

加载 gallery/api/library.json（157 卡）：energy × 叙事匹配 +8（hook 高能/quote 收束/proof 持续）、时长体质校验（stretch 通用 / loop 长镜头金句 / fixed ±35%）、模式卡类别加权（A 模板卡 / B 素材卡 / C 氛围卡）。

✅ 三模式真实文案验证（19 镜头）

模式主体分布效果
A · Remotion 主导remotion 14 (74%) / material 4 (21%) / aigc 1 (5%)零重复卡、语义命中（真相→fracture、研究发现→ring-diagram、方法→method 池）、pit 一致性 0 冲突
B · 人像口播主导person 8 (42%) / material 7 (37%) / remotion 4 (21%)口播主体落地（person 镜头素材全屏）、素材优先规则生效

结论：镜头库不再清一色模板——主体混合（模板/素材/口播/AIGC）、语义匹配、零重复、坑位一致，编导混乱问题在决策层已闭环。

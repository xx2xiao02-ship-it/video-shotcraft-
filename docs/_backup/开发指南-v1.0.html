二、启动与停止
启动操作台：双击 start-console.bat，或命令行 node console-server.mjs（在 E:\video-shotcraft 下）→ 浏览器自动打开 http://127.0.0.1:8765
停止：关闭运行窗口；或任务管理器结束 node 进程。
端口占用排查：netstat -ano | findstr 8765 → 找到 PID → taskkill /PID <PID> /F
工作台/其他入口：Remotion Studio（npx remotion studio）、Motion Workbench（node workbench/scripts/open.mjs）、Gallery（gallery/ 静态站）都从操作台卡片进入。

四、核心管线原理（三步串起来）
Step 1 · tts.py（C1→C2/C6）
读 _input.txt → edge-tts 合成整段语音 → ffprobe 读真实时长 → 按句子字数比例分配每句 start/duration → 写 timing.json + voiceover.mp3。
注意：时长按字数比例估算，句间真实停顿会累积偏差——这就是字幕对不齐的根源（已修复为 ffprobe 读真实总时长 + 去掉虚假停顿）。
→
Step 2 · build-storyboard.mjs（C2→C3）
读 timing.json + taxonomy.json → 每句：判定镜头类型（L1/L2）→ 按时长选镜头卡（快/标准/循环节奏）→ 坑位治理（slot + 素材角色）→ 语义词典提标签 → 素材库检索匹配（时长≥70% + 标签≥2 + 打分排序）→ 未命中 fallback 渐变占位 → 合并超短镜头 → 注入主题 → 写 storyboard.json。
→
Step 3 · render.mjs（C3→C7）
读 storyboard.json → 写 props.json → 调 npx remotion render src/index.ts DynamicVideo → 用本机 Chrome 无头渲染（--concurrency=1）→ 产出 template/out/dynamic.mp4。
分级体系：L1 六类叙事（钩子/痛点/论点/论据/金句/行动）→ L2 26 类细分（含匹配正则）→ L3 镜头卡映射。
三模式：A=Remotion 主导（已闭环）· B=人像口播主导（未开发）· C=AIGC 素材主导（未开发）。模式决定 pit 配置（subject/content/position）。

六、常见问题排查
1. 字幕与语音对不上 → 检查 tts.py 是否用 ffprobe 读真实时长（已修复）；重跑 A 模式验证；确认 timing.json 每段 start 连续。
2. 渲染报错/失败 → 看渲染日志；确认 Chrome 路径存在；--concurrency=1 已固定；磁盘空间充足。
3. Python 找不到/版本错 → 必须用 C:\Users\Administrator\AppData\Local\Python\bin\python.exe，勿用系统 python。
4. edge-tts 合成失败 → 网络问题，脚本已内置 3 次重试；仍失败检查网络后重跑。
5. 端口 8765 被占用 → netstat -ano | findstr 8765 → taskkill /PID <PID> /F。
6. 素材匹配不到/全是渐变占位 → 素材标签太少；去素材库补标签（写 C5）后重新生成分镜。
7. 操作台调接口 404 → UI 与 server 契约未对齐（见设计文档 P0），等待契约治理后统一。
8. 修改后没生效 → 检查是否绕过收敛节点：改主题应写 C4、改素材应写 C5、改分镜应写 C3（见设计文档第五章）。

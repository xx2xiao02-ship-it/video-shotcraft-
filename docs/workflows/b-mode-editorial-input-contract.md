# B模式编导输入契约修补

本规则补齐生成器输入和发送前自检，不改变原版校验、真实配音、口型、字级时间或已审模板构图。

## 正式入口

操作台通过 `/api/talkcraft/intent` 进入正式编导子进程 `director/talkcraft-ark-editorial.mjs`。不得用临时生成脚本代替该入口。

## 发送前必须满足

1. 108张已审卡的业务字段、素材槽位和DSL与正式目录逐项一致。
2. 请求包含锁定校验器的完整 `crossFieldChecks` 函数。缺失、被替换或与正式源码不同，立即阻断发送。
3. 每张卡提供0基驻留上限 `nativeFrames-2`、额外冻结帧数与比例预算。普通卡维持60帧及镜头50%的限制；内嵌音视频卡的额外冻结预算为零。
4. 请求自检独立核对上述边界；不得依靠提示语存在就声称输入已完整。
5. 仍须检查真实句边界及已生成人物精确窗口的数值可行性。该检查不替编导选卡，不证明语义、素材或视觉通过。

## 失败处理和状态

- 自检失败时不发出模型请求，不消耗新授权，不改写制作节点通过状态。
- 请求完整不保证模型返回合规。返回结果继续按原正式校验处理，失败不得自动重复计费。
- 单次模型授权已使用时，必须取得新的单次授权才能再次请求。删除的失败草案不得自行恢复。
- 代码测试、请求自检、04分镜校验、后续制作及用户人审分别记录；旧视频不得替代新任务结果。

## 回归与版本保存

运行编导请求自检、规划契约、原生帧计划、分镜生成器及冻结/人物规则的相关测试。必须覆盖规则函数缺失/被替换、驻留上限变化、冻结预算变化，以及内嵌媒体被错误允许冻结的拒绝场景。

使用同一组输入和测试对照提交基线与修补版。只保存本次生成器、规划契约、自检、测试和本说明，不混入调度、界面、历史素材及运行状态。项目全量测试失败时按版本保护Skill处理，不用专项测试冒称全量通过。

# B 模式整片音轨与人物视频解码隔离

## 根因与修复边界

任务 36f88f5c 的第 17 镜透明 VP9 素材为 30fps、417 帧、13.9 秒，完整解码通过，分段画面已正常生成。失败发生在整片 WAV 导出：上游 render_shots 传入 audioOnly=true，但保存的 Main 不处理这个参数，仍然挂载静音 OffthreadVideo，多页音轨渲染因此触发不必要的视频帧读取失败。

不重做配音、数字人或分镜，不改时间轴、模板、字幕、口型和已审核 Main，不通过截尾、循环或变速掩盖解码错误。

## 固化路径

1. 保留原版视频段渲染、帧数检查和画面拼接。
2. 用已有 prepareSfxSoloProject 的 full-audio 用途创建临时音轨工程。沿用已有 TypeScript AST 提取，只保留正式 Main 的 Audio 表达式，保留配音、BGM、音效的条件、时间、音量及速率；不挂载人物、模板和字幕组件。无法安全提取或 Audio 表达式混入视频时阻断。
3. 正式 Main、素材、字级时间及已审核样片保持原样。副本仅在本任务 .render-temp 内，public 和锁定依赖引用现有安装。复制时保留音频配置 mtime，避免改变原版音轨指纹。
4. 使用原版 render_shots 在音轨副本中导出全长 WAV，按原版指纹、时长检查并与原画面混流。此时视频段来自刚完成并校验的正式视频 pass，禁止在纯音轨工程中用空画面补缺段。
5. 后端继续正式绑定、机器 QA，再停在整片人工审核。机器检查不代表用户验收。

恢复和检查经现有后端继续意图/阶段执行记录同步状态，不重复调用方舟、TTS 或 RunningHub。失败日志与原素材保留。

## 回归与版本依赖

覆盖真实 Audio 表达式保留、纯音轨无视频组件、配音/BGM/音效时钟及速率、未知结构阻断、原工程不改写、配置 mtime 保留、运行依赖锁定及旧产物保留。

SHA256 锁定的契约模块使用 .gitattributes 固定 LF 检出，避免 Windows 自动换行导致相同 Git 提交被误判为契约篡改；不改哈希清单、不放宽校验。

## 13 节点音效轨导出

音效独立轨通过 talkcraft-wav-render.mjs 调用与上游相同的 bundle/selectComposition/renderMedia API。读取原工程打包、浏览器配置；WAV 不接收 CRF、像素格式、JPEG 质量等视频编码参数。保留 sfxSolo=true、audioOnly=true 和原音效表达式，不加载配音/BGM或人物视频。

只重跑机器质检及其音效轨导出，复用现有 final.mp4、配音、人物、字级时间和模板。既有音效轨缓存指纹、时长、完整解码、音效及混音检查原样执行；失败仍阻断，不自动重渲整片、不新增供应商请求。通过后停在整片人工视觉审核，不自动确认。

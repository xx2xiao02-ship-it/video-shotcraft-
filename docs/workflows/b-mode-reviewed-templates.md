## 固定工作路径

大模型是编导：负责语义、镜头分组、叙事安排和已有模板的内容参数；模型不生成场景源码，不设计新组件。`visual` 只作编导说明，不能作为绘图或执行指令。模型给出的 `shotCard` 只是一项提议，必须通过后端的真实候选确认；提案检查通过不能标成选卡通过。模板最终实现由后端复制原源码并绑定参数完成。

原版允许有限蒙皮、纯文镜G5图解及有理由的语义偏离。用户本次确认的“仅已审模板、禁止补画、候选外不放行”收紧了这些许可；不应将本地更严格约束冒称为原版原文。

1. 从历史真实媒体审查记录建立源码版本登记。登记必须包含模板标识、源码及依赖哈希、横竖版样本哈希、参数绑定和布局检查结果。
2. 使用上游 `card_match.py`，输入索引只保留登记且源码版本未变化的模板。按语义、素材、原生时长排序；不把全目录或开场短卡池直接当语义候选。
3. 编导从当前候选明确选卡，逐镜填业务参数。连续30镜不重复。候选不足应补真实素材或重新规划，不允许通过补画、伪造候选或偏离说明放行。
4. 候选、语义、SHOTBOOK 和审查登记绑定版本。输入改变后必须重新生成候选。预检、实现、样片、整片和交付再次核验。
5. 只用模板原生已审参数修改文字、配色及素材。禁止新增图解、隐藏绘图层或在外层CSS覆盖几何结构。原卡无法容纳内容时重新选卡或修改分镜。
6. 复用原配音和现有人物口型素材，保留原片与旧候选。模板替换仍须检查字级、素材时间范围、布局、对比度、实际编码视频和音轨一致性。

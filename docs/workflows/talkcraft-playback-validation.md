# 正式成片播放与状态核验

- `/api/talkcraft/status`、`latest`、正式视频 Range 请求及自动推进的状态读取，通过独立核验线程执行原 `readTalkcraftStatus` 全部检查，避免同步文件读取和源码核验阻塞 HTTP 视频流。
- 仅合并同一任务正在执行的核验，不缓存已经完成的通过结果。下一次查询重新核验；原错误原样拒绝。线程异常时当前请求失败，不能以旧状态放行。
- 每次正式视频请求只使用一次完整核验结果决定来源、成片和交付状态，保留原来源门禁。交付/审核写入仍执行原校验，未改变业务规则。
- 核验期间已建立的视频流必须继续发送；验证同时轮询状态及拖动视频，不能仅以 HTTP 200/206 证明流畅。保留现有成片、声音、人物及时间轴，不重新生成素材。

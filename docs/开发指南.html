已确立的三条整改基线（对应历史事故，必须长期执行）：
基线 A · 切词单点化：文案切词只在 build-storyboard 做一次，storyboard 直接给最终 chunks；渲染层（TemplateAdapter）只消费，禁止二次切词覆盖（历史事故：渲染层 splitToWords 6字硬切 → "刷到一条好视/频"碎块）。
基线 B · 模板能力自描述：模板行为由 registry 声明（textMode raw/chunk/carrier、tone、style、capacity、媒体需求），编导层读声明选模板，禁止靠名字猜行为（历史事故：clipcard 是演示 demo、filmstrip 固定英文大字，编导层不知道）。
基线 C · 风格 token 化：颜色/字体/字号由主题下发，组件零硬编码（禁止英文 demo 文案/预置字体/参数 UI——历史事故：clipcard 参数面板、vertical-roll "Built for" 残留）。

启动操作台：双击 start-console.bat，或 node console-server.mjs（E:\video-shotcraft 下）→ http://127.0.0.1:8765
渲染前必须确认 8765 在监听：渲染时组件要拉素材流 http://127.0.0.1:8765/api/library/video?path=...，服务没起 → connect ECONNREFUSED 127.0.0.1:8765（历史事故）。检查：Get-NetTCPConnection -LocalPort 8765

端口占用：Get-NetTCPConnection -LocalPort 8765 -State Listen → 结束对应 OwningProcess。

四、模板选择硬规则（基线 B：5 条不可违反）
规则 1 · 容量优先于坑位类型。文案容量收敛先于坑位类型：长文案跨池匹配 long 承载模板（list-reveal / list-stack-press / clipcard 已禁则走 list 系 / bezier / neon-frame），绝不硬塞大字卡；池内无匹配 → 全库按容量差距选 top5；真无 → 降级链。容量档：short≤10 / medium≤26 / long≤60。
规则 2 · 三维度打分（U1-U7）。① tone 色调：dark 26 / light 8 / colorful 1，主题深色为主，一致 +15、冲突 -10、与上一镜头同色 +8/-8；② style 视觉语言：typographic 主家族 +12/-8，相邻同风格 +8/-10（衔接一致性就是靠这个维度）；③ capacity 容量（规则 1）。收敛报告逐镜头输出 容量[OK/⚠] 色调OK 风格OK。
规则 3 · 整句/碎块硬分流。FULL_SENTENCE_CARDS 整句类（打字机/列表/卡片/滚动）接 ≤22 字完整句，7 字以上 +15；WORD_CHUNK_CARDS 碎块类（词块/接力动画）仅 ≤6 字短词。文案一律整句呈现，禁止把句子切成静态大字块（历史事故："刷到一条好视/频"、"那条视频/你大"）。
规则 4 · 黑名单（BLOCKED_CARDS，永不入选）。ui-entrance/clipcard-looping（Remotion 演示 demo，硬编码参数 UI + demo 视频）、typography/word-relay-filmstrip（固定英文大字 "Computer" 首行）、typography/vertical-word-roll-blur-cycle（"Built for" 英文残留 + 切块）、typography/lead-word-zoom-assemble（"One shot card" demo 残留 + 长句挤爆）。新增模板入库前必须验证无英文残留/无参数 UI/无演示 demo。
规则 5 · 降级链（禁止渐变占位）。模板无匹配 → 先找纯素材当画面（findMaterial，素材时长与镜头时长接近优先，durGap×3 权重，minDur 0.85 + 不够长重罚 -20）→ 素材也无 → aigc={prompt,status:pending}（genAigcPrompt 按类型/情绪生成视频提示词，渲染显示"AI 生成镜头·待生成"占位）。渐变占位在代码中已彻底移除，禁止重新引入。
五、耦合契约（本轮确立的整改方向，落地中）
A · 切词单点化（已部分落地）
文案切词只在 build-storyboard 一次（storyboard 给出最终 chunks）；TemplateAdapter 只消费、禁止覆盖。splitToWords 仅作无 chunks 时的兜底。目标：渲染层对文字零加工。
B · 模板能力自描述（下一步）
registry 从"参数统计"升级为"行为契约"：textMode(raw/chunk/carrier)、tone、style、capacity、媒体需求（组件媒体/背景/无）。编导层读声明选模板，名单机制（FULL_SENTENCE/WORD_CHUNK/BLOCKED）最终由声明取代。
C · 风格 token 化（持续执行）
颜色/字体/字号由 current-theme.json（C4）下发，组件零硬编码。发现组件内硬编码英文/字体/颜色 → 改为消费 token。新增/修改组件时强制执行。
六、RED FLAG 禁止清单（改代码前逐条对照）
① 禁止黑名单模板入选（clipcard-looping / word-relay-filmstrip / vertical-word-roll-blur-cycle / lead-word-zoom-assemble）。
② 禁止渲染层（TemplateAdapter / 组件）二次切词覆盖编导层 chunks——文字形态由编导层唯一决定。
③ 禁止组件内硬编码英文 demo 文案 / 预置字体 / 参数 UI（muted=、startFrom、Computer、Built for、One shot card 等均为事故先例）。
④ 禁止在 build-storyboard 内硬编码模板名直选绕过打分链（历史事故：素材主体 35% 概率直选 clipcard）。
⑤ 禁止绕过收敛节点改数据：改模板能力写 template-registry.json、改主题写 current-theme.json、改素材写 _index.json、改分镜逻辑写 build-storyboard.mjs——禁止改 storyboard.json 后手工覆盖（它是生成产物）。
⑥ 禁止重新引入渐变占位兜底（降级链只允许：纯素材 → AIGC pending）。
⑦ 禁止渲染前不确认 8765 服务在监听；禁止整杀 node.exe（会连带杀掉 console-server）。
⑧ 禁止改完代码不更新本文档基线（任何新规则/新黑名单/新降级链必须沉淀进本文档与 registry._meta）。
⑨ 禁止在未重新生成 storyboard 的情况下直接渲染（props 必须是本轮生成结果）。
⑩ 禁止将验证帧 _chk_*.png / _render_log.txt 提交入库（已在 .gitignore）。
七、提交前验收流程（每次改动必走）
Step 1 · 改逻辑：node director/build-storyboard.mjs → 看收敛报告：每镜头 文案N字 容量[OK] 色调OK 风格OK；0 渐变占位；坑位分布正常。
Step 2 · 改视觉：抽帧验证 ffmpeg -ss <t> -i template/out/dynamic.mp4 -frames:v 1 _chk_xN.png → 核对：文案完整整句、无英文残留、无碎块、无参数 UI、无黑名单模板。
Step 3 · 全片：node director/render.mjs（渲染前确认 8765 监听；4-6 分钟）→ ffprobe 核验时长与语音对齐。
Step 4 · 提交：git add -A && git commit -m "fix/feat: ..." → git push origin main（验证帧不入库）。
Step 5 · 沉淀：新规则写回本文档 + template-registry.json 的 _meta 治理沿革。
八、常见问题排查
1. 渲染报 connect ECONNREFUSED 127.0.0.1:8765 → console-server 没起，先启动再渲染（见第二章）。
2. 渲染中组件报错（如 ReferenceError: words is not defined） → 组件 props 名与 TemplateAdapter 契约不符，查组件签名与契约（基线 B）。
3. 文案出现碎块 / 英文残留 / 参数 UI → 命中黑名单或渲染层二次切词，对照 RED FLAG ① ② ③ 逐条排查。
4. 字幕与语音对不上 → tts.py 是否 ffprobe 读真实时长；timing.json 每段 start 连续；渲染前重新生成 C3。
5. E 盘不可访问 → 外接盘掉线，重新挂载后继续（历史事故：E:\video-shotcraft 整体读不到）。
6. 系统卡死 → 多为渲染进程异常/磁盘打满，任务管理器结束该 node 进程（勿整杀）。
7. 素材匹配不到 → 素材标签太少，补 _index.json 标签后重新生成分镜。
8. 改了没生效 → 是否绕过收敛节点（RED FLAG ⑤）；或渲染用了旧 storyboard（RED FLAG ⑨）。

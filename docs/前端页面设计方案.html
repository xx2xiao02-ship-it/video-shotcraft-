Video ShotCraft · 前端页面设计方案
v1.1 · 2026-09-21 · 基于《业务主线与模块分工》框架 · 对应项目 E:\video-shotcraft
文档目的：把当前"单页堆叠"的操作台（console-ui.html，1394 行 / 62KB，7 个业务环节共用一页），按业务主线重构为 5 视图工作台。 每视图聚焦一个业务环节，同时治理前端与后端 API 契约不一致的问题（UI 仍在调用 /api/logs、/api/action、/api/state、/api/preview、/api/materials 等旧接口，server 已改为 /api/task、/api/storyboard 等新接口）。
v1.1 新增：五、关键数据收敛节点（收敛规则）；六、数据契约与 mock 示例（16 个接口的请求/响应样例，基于真实文件结构）；验收标准增加 Mock 验收与收敛校验。
一、设计目标与原则
① 按主线分视图
编导→制作→成片三条主环节各自独立视图，素材库与风格中心单独成页，一屏一职责。
② 接口契约治理
UI 与 server 的 API 对齐为唯一清单，消灭 404 与"调了没反应"的隐性故障。
③ 渐进迁移
不推翻现有逻辑：视图拆分先搬功能，业务逻辑与素材/风格/渲染管线代码原样保留。
④ 保持轻量
本地工具定位不变：单文件 HTML + 原生 JS，不引入框架依赖，刷新不丢状态。
⑤ 修改收敛（v1.1）
一切修改只落在关键数据收敛节点（权威文件）上，在收敛范围内调整；禁止绕过收敛节点的散改（如直改组件硬编码色、写死素材路径）。

四、导航与状态串联
主流程状态机：编导台（保存）→ 制作台（自动刷新分镜）→ 渲染完成 → 成片台（自动显示预览）→ 交付（工作台/剪映）
状态持久化：页面切换存 sessionStorage（当前视图/模式/主题/最近任务 id），服务端状态以收敛节点文件为权威源（C1-C7）
跨视图共享：主题选择（风格中心，C4）影响 storyboard.json theme（C3）；素材打标（素材库，C5）影响分镜素材匹配结果——两处修改后回到制作台需提示"重新生成分镜"。

5.2 收敛规则 —— 所有修改必须在收敛范围内调整
R1 文案修改：只经 C1（编导台保存 → _input.txt），随后重跑管线（C2→C3→C6→C7）。禁止直接改 C3 中的 text 字段当"偷改文案"。
R2 风格修改：只经 C4（风格中心 → theme-pack.json → 注入 C3.theme）。禁止绕过 C4 直改 221 个组件的硬编码色。
R3 素材修改：只经 C5（素材库上传/打标 → _index.json）。禁止在 C3 中写死素材路径（校准替换除外，且同样回写 C3）。
R4 分镜修改：只经 C3（制作台校准/单镜头覆盖 → storyboard.json）。渲染一律读 C3，不读散落的中间态。
R5 单向回流：任何视图的修改最终必须落到 C1-C5 之一；sessionStorage / 内存态只承载临时 UI 态，不承载业务数据。
R6 收敛校验：修改操作完成后，检查对应收敛节点文件（mtime + 内容）已更新；发现未落盘即视为失败。
六、数据契约与 mock 示例（v1.1 新增）
6.1 使用规则
1. 前端每个 API 封装一层 fetcher；fetch 失败或接口未实现时返回内置 mock payload（放 console-ui.html 顶部 const MOCK = {...}）。
2. mock 字段必须与真实文件结构一致（本章示例即模板，已按 storyboard.json / timing.json / _index.json / theme-pack.json 实际结构编写）。
3. P0 验收：断开 server（接口 404）时，5 视图用内置 mock 跑通全流程，证明数据管线已打通；接通 server 后逐接口替换为真实数据。
4. 新增接口（/api/library/tag、/api/library/stat、/api/theme、/api/theme/save）由 server 按本章契约实现，前端按同一契约开发。

七、与现有代码的迁移关系
保留不动：console-server.mjs 全部业务逻辑与现有 API、materials 索引与缩略图、风格参数面板逻辑、进度轮询逻辑、storyboard-review.html 独立校准页。
拆出迁移：快捷入口卡 → 成片台交付区；编导表单 → 编导台；进度+校准 → 制作台；风格卡片 → 风格中心；素材库区 → 素材库视图。
接口对齐（P0）：UI 中 /api/logs → /api/task、/api/action → server 实际命令、/api/state → server 状态接口、/api/preview、/api/stream、/api/materials → 收敛到唯一 API 清单，删除或实现缺失接口。
新增接口：/api/library/tag、/api/library/stat、/api/theme、/api/theme/save（按第六章契约实现）。
八、落地优先级
P0 · 契约对齐 + Mock 骨架
接口清单对齐；MOCK 常量内置；5 视图 Tab 导航 + 状态栏；断网可跑通全视图。
P1 · 素材库视图
标签编辑/批量打标（写 C5）+ 分类统计；情绪标签与使用频率降权。
P1 · 风格中心
theme-presets.json + 批量应用 + 选择下拉（写 C4）；统一 221 组件硬编码色调。
P2 · 制作台增强
单镜头覆盖（镜头卡/素材/文案，写 C3）、渲染日志展开、完成后自动跳转。
P3 · 成片台集成
交付出口卡片整合；成片元信息展示；B/C 模式按钮接入。
九、验收标准
1. 5 个视图可独立打开、互相切换，刷新后不丢当前视图与模式状态。
2. 主流程闭环：编导台保存 → 制作台自动出分镜 → 渲染 → 成片台出预览，全程无手动刷新。
3. 接口契约：浏览器 Network 面板无 404、无未对齐 API（旧 /api/logs、/api/action 等清零）。
4. 素材库打标后可立即影响下一次分镜匹配（重新生成分镜可见素材变化，收敛节点 C5 生效）。
5. 风格中心切换主题后，重渲染成片色调整体一致（无组件硬编码色残留，收敛节点 C4 生效）。
6. Mock 验收（v1.1）：断开 server（接口 404）时，5 视图用内置 mock 数据完整渲染，无白屏、无脚本报错，主流程可走通。
7. 收敛校验（v1.1）：打标/主题/校准/文案任一修改操作落盘后，对应收敛节点文件（C5/C4/C3/C1）mtime 与内容已更新；代码审查中无绕过收敛节点的直接修改路径（如直改组件硬编码色、写死素材路径）。
